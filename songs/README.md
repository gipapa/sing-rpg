# 加密 ChordPro 歌本

網站以 AES-256-GCM 加密檔儲存歌本。每次加密使用新的隨機 96-bit IV，並以 128-bit 驗證標籤檢查資料完整性。歌曲名稱、歌詞、和弦與其他 ChordPro 內容都在密文裡；`index.json` 只有可公開的歌本標籤與檔名。

## 準備歌本

使用支援 ES Modules 自動辨識與 Web Crypto 的新版 Node.js（建議 Node.js 22.18 以上）。將你有權使用的 `.cho` 放在此專案目錄之外，再執行：

```sh
node scripts/encrypt-songbook.mjs \
  --out songs/my-songbook.enc.json \
  --key-file ~/.config/sing-rpg/my-songbook.key \
  ~/my-scores/song-a.cho \
  ~/my-scores/song-b.cho
```

金鑰不存在時，工具會產生一把隨機 256-bit 金鑰，寫入 `--key-file` 指定的位置，權限設為僅檔案擁有者可讀寫。已存在的金鑰會沿用，方便同一本歌本更新時繼續使用。工具不會印出金鑰，也不會覆寫既有輸出；更新時請指定新檔名，確認成功後再替換舊檔。

明文譜與金鑰必須位於專案之外，工具會檢查實際路徑，包括指向專案內的符號連結。`.gitignore` 另排除 `.key`、`.pem` 與 `songs` 下常見的明文譜副檔名，僅保留無歌曲內容的 `.template.cho` 範本。這是避免誤提交的輔助，不能取代將秘密放在專案外。

一本歌本支援 1–100 首歌，加密前的 JSON 資料最多 2 MB。

## 加入清單

編輯 `songs/index.json`：

```json
[
  { "label": "我的歌本", "file": "my-songbook.enc.json" }
]
```

`file` 是相對於 `songs/` 的檔案位置，只接受本站 `songs/` 下的檔案。`label` 是公開文字，請不要填入你想保密的資訊。只有加密檔與這份清單需要發布。

## 閱讀

1. 自己開啟音樂，回到遊戲。
2. 在營地按「加密歌本」，或遠征時按「♬ 歌本」。
3. 選擇歌本，將金鑰檔內完整的 `sing-rpg-key-v1.…` 貼入「解密金鑰」。
4. 選曲閱讀，可移調、調整字體與自動捲動速度。移調只改顯示的和弦，不會調整外部播放音樂的音高；Capo 顯示原譜數值。
5. 關閉歌本視窗後，同一次頁面仍可再開啟。按「鎖定歌本」、重新整理或離開頁面後，需要重新解鎖。

金鑰不會加入網址、網路請求、`localStorage` 或 `sessionStorage`。程式只在本次頁面記憶體內使用金鑰與明文，鎖定時清除持有的譜面與 DOM；字體與捲動速度可以保存在瀏覽器。背景切換、手動觸控或滾輪操作會暫停自動捲動，捲動不會與外部音樂同步。

讀譜器支援基本歌曲資料、行內 `[C]` 和弦、主歌／副歌等段落、註解與文字 TAB。未支援的獨立指令會略過，所有譜面文字都以純文字呈現，不執行 HTML。這不是完整的 ChordPro 排版引擎。

## 示範與存取限制

`demo.enc.json` 包含兩首原創示範譜。此工作階段產生的示範金鑰位於本機 `~/.config/sing-rpg/demo-songbook-20261114.key`，沒有放進 repo。另一部電腦需要另外取得金鑰；不會自動從網站取得。

這裡使用的是對稱式秘密金鑰，不是可公開分享的公鑰。任何取得金鑰的人都能解密、檢視與複製譜面；公開 repo 裡的密文也能被下載。這不提供到期、撤銷、DRM 或使用者帳號權限，遺失金鑰則無法復原。若舊金鑰外流，替換成新金鑰只保護新版本，不能讓已下載的舊密文失效。

加密僅處理存取方式，不代表取得歌詞或曲譜的重製、散布與公開傳輸授權。
